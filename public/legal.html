Privacy Policy

RadioDock (radiodock.app) is operated by the person named above and hosted on GitHub Pages. During normal use the application does not collect personal data: your favourites and custom station lists are stored locally in your browser via IndexedDB and never leave your device. The one exception is the optional “Add → Submit station” form, where you deliberately send us the data you type — see Station submissions below.

Third-party services accessed when you use the app

  • RadioDock Stations API (stations.radiodock.app) — when you search for stations or open a station's info panel, your query is sent to our own curated station database, operated by the same person. The application writes no request log: your IP address is held in memory only for the duration of a rate-limiting window (one minute) and is then discarded. Where an IP has to persist at all — spam limits on station submissions and on Detect — only a salted, one-way SHA-256 hash is stored, never the address itself.
  • Radio Browser API (*.api.radio-browser.info) — the community-run directory our station data is built from. It is contacted directly from your browser only as an automatic fallback, if our Stations API is unavailable. Privacy info.
  • Station logos (stations.radiodock.app/logos/…) — station artwork is served only from our own origin, looked up by station ID. The app no longer loads station favicons directly from third-party websites or an icon service, so opening the app does not leak your IP to dozens of external hosts before you interact with it. If a logo is unavailable the app shows a plain initials chip.
  • RadioDock Metadata Proxy (stations.radiodock.app, with radiodock-metadata-proxy-1.onrender.com as a fallback) — when you play a station, the stream URL is sent to this proxy to fetch "now playing" metadata. The proxy is operated by the same person; source code is open at GitHub. Unlike the Stations API, this proxy does write an operational log line per request, containing timestamp, request path, response status and your IP address; query values other than the stream URL are redacted before logging. On the Render fallback instance these logs are deleted automatically after 7 days under Render's log-retention policy.
  • Radio stream servers — your browser connects directly to each station's stream server when you press play. We are not the operator of those servers; refer to each station's own privacy notice.
  • RadioDock Stations relay (stations.radiodock.app) — only when you actively record a station, its audio stream is routed through our own server instead of connecting directly, so your browser can capture it. The server relays the bytes live and never stores them; the recording is saved only on your device (IndexedDB). The relay runs on the Stations server described above and therefore writes no request log either.
  • RadioDock Stations recorder (stations.radiodock.app) — on mobile, recording is done on our server because your device's browser can't capture the audio directly. The stream is briefly buffered on the server and deleted immediately after it is transferred to your device; it is never stored long-term. The recording lives only on your device (IndexedDB).
  • RadioDock Stations track detection (stations.radiodock.app) — only when you tap Detect, roughly 12 seconds of the station's current audio is captured on our server (the stream URL is looked up by station ID, never taken from your device) and sent to a cloud music-recognition service (ACRCloud's EU endpoint and/or AudD) to identify the track. Only stream audio — no personal data — leaves the server, and only on that tap; the audio is held in memory and never stored. If the service is unavailable, only Detect is affected — playback and search are not. A detected result is saved as a note on your device only. If you expand a note to preview it, a Spotify/YouTube embed is not loaded automatically — it loads only after you tap "Load preview", at which point your browser connects directly to Spotify and/or YouTube. Your choice can be remembered locally on your device, and you can disable external previews again at any time from within a note.
  • GitHub Pages (host of this site) and Render.com (host of the metadata proxy) record standard server logs (IP address, browser type, timestamp). See GitHub's privacy statement and Render's privacy statement.
  • Buy Me a Coffee — only accessed if you click the "Support" link in the footer. See their privacy policy.

Storage periods

  • Stations server (search, station info, logos, recording relay and recorder, Detect) — no request log is written. Your IP address exists only in server memory for a one-minute rate-limiting window; the salted SHA-256 hashes used for spam limits are kept only as long as the corresponding limit or submission record.

  • Station submissions — as described under Station submissions.
  • Hosting providers — GitHub, Render and Hetzner keep their own standard server logs under their own retention policies, which we do not control.

Station submissions (the “Add” form)

RadioDock lets you propose a station for the community database via Add → Submit station. This is voluntary. When you submit, the data you enter is sent to and stored on our own Stations server (stations.radiodock.app), which runs on a Hetzner server located in Germany — the data stays within the EU. (The separate Add → Custom stream feature is purely local: it only writes to your device via IndexedDB and sends nothing to us.)

What a submission contains:

  • Personal data you provide about yourself: a username (required, for attribution) and an optional email address (only if you want a moderator to be able to contact you). If you leave the email blank, none is collected.
  • Station data you provide: name, stream URL, info, tags, homepage, an optional logo image, now-playing-metadata settings, and optional station socials, city, and a public station contact email. Please only enter a third party's contact details if you are entitled to share them.
  • Automatically added: a one-way hash of your IP address (used purely for spam rate-limiting; the raw IP is never stored) and a timestamp.

Purpose & legal basis: the data is processed to review, moderate, and (if suitable) publish the proposed station, to credit the contributor, to optionally follow up with you, and to prevent spam and abuse. Legal basis is Art. 6(1)(f) GDPR (legitimate interest in curating a community station database and keeping it spam-free); the optional email is provided on the basis of your consent, Art. 6(1)(a) GDPR, which you can withdraw at any time.

What becomes public: if a submission is approved, the station details become part of the public station database. Your username and email are never published — they remain visible only to the site operator for moderation.

Retention: submissions are kept while they await review and, once decided, are retained only as long as needed to run the database and prevent the same entry being re-submitted (rejected stream URLs are remembered to stop re-queuing). You can ask us to delete your submitter data at any time using the contact address above.

Recipients: the data is handled only by the site operator on the self-hosted Stations server. It is not sold or shared with third-party advertisers or analytics providers.

Cookies & local storage

RadioDock sets no HTTP cookies and no tracking identifiers. It does store data locally on your device, all of it purely functional and none of it transmitted to us:

  • IndexedDB — your favourites, custom station lists, notes and recordings.
  • localStorage — your light/dark theme choice (radiodock-theme), your analytics opt-out flag (umami.disabled) and, if you set one, your preference for loading external Spotify/YouTube previews.

All of these store or read information on your terminal equipment only to deliver a function you have expressly requested, so they are exempt from the consent requirement under § 25 Abs. 2 Nr. 2 TDDDG (the German implementation of the ePrivacy Directive, formerly the TTDSG). You can clear them at any time via your browser's site-data settings.

Analytics (Umami)

RadioDock uses a self-hosted instance of Umami (open-source, privacy-friendly analytics) running on the operator's own server hosted in Germany (Hetzner). All analytics data stays within the EU — there is no third-party analytics provider and no transfer to a third country. Umami does not set cookies, does not store persistent identifiers on your device, does not fingerprint your browser, and does not track you across sites.

What is recorded: pageviews, and a small set of named interaction events (which station was played and — via an anonymous once-per-minute "listening" event — for roughly how long, including whether the app was in the foreground or background at that moment and the show/track name the station itself broadcasts; which install button was clicked; search filter used; list created/imported/exported/deleted; stream errors and recoveries). The events do not contain any text you have typed (no search queries, no list names, no station notes), and the listening events carry no identifier linking them to you or your device.

What Umami briefly processes: your IP address is used on the Umami server to derive a country code and to generate a daily-rotating, hashed session identifier. Neither the IP nor the session hash is retained after the day rolls over, and neither is exposed to the site operator.

Legal basis: Art. 6(1)(f) GDPR — legitimate interest in understanding aggregate product usage to improve the app. The analytics script itself neither stores information on nor reads information from your terminal equipment, so the consent requirement of § 25 Abs. 1 TDDDG is not triggered; the only value written locally is your own opt-out flag, which is strictly necessary to honour your choice and is exempt under § 25 Abs. 2 Nr. 2 TDDDG. You can object to this processing at any time under Art. 21 GDPR using the toggle below.

How to opt out: use the toggle below, or enable "Do Not Track" in your browser, or use any content blocker. RadioDock works identically with analytics off.

Further reading: Umami is open-source software (see umami.is). Because RadioDock runs its own instance, usage data stays under the operator's control and is never passed to a third-party analytics company, so no Art. 28 GDPR data-processing agreement with an external provider is involved.
